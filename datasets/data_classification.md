# Классификация синтетических данных

## Назначение

Этот документ определяет уровни классификации данных, используемые в проекте Banking AI Antifraud & Data Loss Prevention Lab.

Классификация применяется при:

- предоставлении доступа пользователям и AI-агентам;
- вызове инструментов;
- формировании отчётов;
- обработке транзакций;
- журналировании событий;
- маскировании значений;
- передаче данных между компонентами;
- экспорте результатов;
- создании инцидентов безопасности.

Все данные проекта являются синтетическими. Уровень классификации показывает, как система должна обращаться с данными в демонстрационной среде.

---

## Основное правило доступа

> Агент не имеет права самостоятельно повышать себе уровень доступа. Уровень доступа определяется политикой, ролью пользователя, назначением агента и контекстом запроса.

AI-агент не может:

- изменять собственный профиль разрешений;
- добавлять себе новые инструменты;
- самостоятельно снимать маскирование;
- расширять область запрашиваемых данных;
- использовать права другого пользователя;
- менять классификацию документа или набора данных;
- отправлять данные в новый канал без проверки политики;
- обходить требование ручного согласования.

Если запрошенный уровень данных превышает разрешённый уровень агента, система должна ограничить, замаскировать, отправить на согласование или заблокировать действие.

---

## Уровни классификации

| Уровень | Содержание | Базовое решение |
|---|---|---|
| `Public` | Публичная информация | Разрешить |
| `Internal` | Внутренняя информация | Разрешить только сотрудникам и утверждённым внутренним агентам |
| `Confidential` | Транзакции, идентификаторы и служебные отчёты | Ограничить, маскировать и журналировать |
| `Restricted` | Полные реквизиты, секреты и результаты расследований | Блокировать экспорт и требовать согласование |

---

# 1. Public

## Описание

`Public` — информация, предназначенная для публичного использования и не содержащая внутренних, персональных, финансовых или служебных сведений.

## Примеры

- публичное описание проекта;
- README и общая документация;
- описание архитектуры без секретных параметров;
- общедоступные инструкции;
- публичная база знаний;
- агрегированные обезличенные показатели;
- описание демонстрационных сценариев;
- общая информация о назначении компонентов;
- безопасные синтетические примеры.

## Правила обработки

Данные уровня `Public` можно:

- показывать внешним пользователям;
- обрабатывать внешним AI-агентом;
- публиковать в GitHub;
- использовать в документации;
- передавать через разрешённый публичный интерфейс;
- сохранять в обычных технических журналах.

3. Confidential
Описание
Confidential — чувствительная информация, доступ к которой предоставляется только при наличии подходящей роли, бизнес-цели и разрешённого контекста.
Примеры
синтетические клиентские идентификаторы;
идентификаторы счетов;
детализированные транзакции;
история действий клиента;
внутренние аналитические отчёты;
события AI-агентов;
результаты риск-скоринга;
данные назначенного расследования;
служебные сведения о сотрудниках;
параметры вызова внутренних инструментов;
связи между клиентами, устройствами и получателями.
Правила обработки
Для данных уровня Confidential обязательны:
проверка роли;
проверка цели запроса;
проверка принадлежности данных;
проверка подразделения;
ограничение количества записей;
маскирование идентификаторов;
журналирование доступа;
контроль исходящего канала;
указание версии применённой политики;
сохранение correlation ID.
Данные уровня Confidential нельзя:
предоставлять внешнему AI-агенту;
экспортировать без утверждённого основания;
передавать в неизвестный канал;
записывать полностью в технический журнал;
включать в публичные отчёты;
возвращать в большем объёме, чем требуется для задачи.

4. Restricted
Описание
Restricted — данные максимальной чувствительности, раскрытие или неправильное использование которых требует немедленного ограничения действия и регистрации события безопасности.
Примеры
пароли;
API-ключи;
токены доступа;
приватные ключи;
полные платёжные реквизиты;
административные данные;
необработанные материалы расследования;
результаты критических антифрод-проверок;
сведения о защитных механизмах, позволяющие обойти контроль;
полный набор данных массового экспорта;
конфигурации с секретами;
контрольные маркеры ограниченного доступа;
данные критического инцидента.
Правила обработки
Для данных уровня Restricted обязательны:
принцип минимальных полномочий;
отдельная проверка доступа;
ручное согласование;
строгий allowlist инструментов;
запрет внешнего экспорта;
запрет записи исходного значения в журнал;
маскирование или токенизация;
полный аудит действий;
ограниченный срок хранения;
регистрация инцидента при нарушении;
возможность приостановки сессии;
возможность отзыва capability или демонстрационного токена.

Правила повышения классификации
Если один результат содержит данные разных уровней, для всего результата применяется самый высокий обнаруженный уровень.

Plaintext

Confidential + Restricted = Restricted

Ограничения
Классификация в этом проекте является демонстрационной и не заменяет внутреннюю политику реальной организации.
Все примеры, идентификаторы, транзакции, документы и инциденты являются синтетическими. Проект не содержит реальных клиентских данных, настоящих платёжных реквизитов, рабочих секретов или внутренних документов банков.
